# 01 要件定義 — 「見えない水」（生成 AI の水消費ビジュアライザ）

作成日: 2026-10-21 / 状態: PoC 段階（置き場所未決、未コミット）

## 1. 背景と目的

生成 AI の利用はデータセンターの冷却のために淡水を蒸発させるが、利用者からは一切見えない。
「1 回の質問で何 mL か」は出典によって桁が違い（事業者公表 0.26 mL 〜 報道の 519 mL）、
片方だけを見せると誇張か過小のどちらかになる。

このアプリは、**使っている最中に、ペットボトル・浴槽・プールといった身体感覚のある器に
水が溜まっていく様子を見せる**。目的は啓発であって告発ではない。数字の幅と出典を隠さず、
見た人が「自分の使い方だと、どのくらいか」を自分の目で確かめられる状態にする。

## 2. 利用者と利用場面

| 利用者 | 場面 | 求めること |
|---|---|---|
| 社内勉強会・講演の登壇者 | スライドの合間にブラウザで開いて見せる | 開いた瞬間に伝わる。操作が 1 つで済む。プロジェクターでも読める |
| 生成 AI を日常的に使う人 | チャット画面の隣に置いておく | 自分の送信回数が水位に直結する。邪魔にならない |
| 記事・SNS で共有された人 | スマホで開く | スクロールだけで理解できる。出典に辿り着ける |

## 3. 機能要件

### F1 世界カウンター（幕 1「いま、この瞬間」）
- ページを開いた時刻からの経過時間 × 1 秒あたりの水量を表示する。基礎は ChatGPT の 1 日 25 億プロンプト（OpenAI → Axios、2025-07）× 選択中のシナリオ単価。
- 表示は L で、桁に応じて mL / L / kL / 万 L に切り替える。数字は等幅（tabular）で揺れない。
- 画面下端に水面があり、累計量に合わせて実時間で上がる。
- 見出しに「ChatGPT だけで」と明記する（全世界の生成 AI の回数は信頼できる推計がないため）。

### F2 シナリオ切替（常時表示）
- 低 / 中 / 高 の 3 シナリオを 1 クリックで切り替えられる。既定は「中」。
- 選択中の単価・出典名・「何を含むか」の一言が、切替 UI の直下に常に出る。
- 切替時に世界カウンターの数字は跳ばず連続する（それまでの累計を保ち、以降の速さだけ変わる）。
- 選択は localStorage に保存する（保存に失敗しても動作する）。

### F3 ライブ計測（幕 2「あなたの一回」）
- 500 mL ペットボトルの中に液体が入っている絵。大きな「送信した」ボタン。Space / Enter でも押せる。
- 押すたびに一滴が落ち、液面が単価分だけ上がる。ボトルが満ちたら本数を数え、新しいボトルに移る。
- 回数・経過時間・累計 mL・換算（ティースプーン / コーヒー 1 杯 / ペットボトル）を表示する。
- 「自動」トグル: 30 秒に 1 回（間隔は変更可）を自動で加算する。実際のチャット作業の隣に置く用途。
- 「リセット」で 0 に戻せる。

### F4 積み上げ試算（幕 3「積み上げると」）
- スライダー 3 本: 1 日の回数（1〜500）、人数（1〜10,000）、日数（1〜365）。
- 合計量に応じて器が切り替わる: 500 mL ボトル → 2 L ボトル → 24 本ケース → 浴槽 200 L → 25 m プール → 東京ドーム。
- 切替はカメラが引く（ズームアウト）アニメーション。前の器が小さくなって画面に残り、縮尺が伝わる。
- 「◯個分」の数字と、その器を何個並べると足りるかの図（上限あり、超過分は数字）。

### F5 根拠（幕 4）
- シナリオ表: 単価、出典（リンク）、年、何を含むか、批判・注意点。
- 換算対象の表: 容量、出典。裏取りできていないものは「目安」と表示する。
- 免責: 推計であること、事業者・地域・季節・モデルで大きく変わること。

### F6 共有と差し込み口（PoC では枠だけ）
- 幕 1 の背景とOG 画像に、後から質感のある画像を差し込める `<picture>` スロット（SVG フォールバック付き）。

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| 配布 | `index.html` をダブルクリックで開けること。ビルド・サーバー・外部通信なし |
| 依存 | ライブラリなし。CDN を参照しない（proxy で 403 になる環境がある） |
| 表示 | ノート PC 1366×768@125%（1093×614）と 1920×1080@150%（1280×720）で文字切れ・横スクロールなし。スマホ幅 390 でも崩れない |
| 可読性 | 本文 1 行の長さは 40 字前後。数字は tabular-nums。ダークモード（`prefers-color-scheme`）対応 |
| 動き | `prefers-reduced-motion` では波・滴を止めて数字の更新だけにする。rAF ループは 1 本、タブ非表示で停止 |
| 性能 | 普及帯のノート PC で 60fps 近く。滴は上限 24、器の複製は上限 48 |
| 機密 | 利用者の入力は保存しない（シナリオ選択のみ localStorage）。リポジトリは public 前提で、社名・個人情報を含めない |
| 言語 | 日本語。英語化は将来（文字列を `data.js` の 1 か所に寄せる） |

## 5. 受入条件（詳細は `04_受入試験.md`）

1. 開いて 3 秒以内に、数字が増え続けていることが分かる。
2. 「送信した」を 1 回押すと、液面が目に見えて動き、回数が 1 増える。
3. シナリオを「低」から「高」に変えると、同じ 1 回でボトルがほぼ満ちることが伝わる。
4. スライダーを右端まで動かすと、器が少なくとも 3 段階ズームアウトする。
5. 幕 4 の出典リンクがすべて実在ページに飛ぶ。
6. 3 視口で横スクロールが出ない。
