# 02 モデルと出典

数値は `src/data/params.json` にだけ書く（`model.ts` と `scripts/water_meter.py` が両方そこを読む）。裏取り日: 2026-10-21。

## 計算の鎖

```
kWh   = トークン ÷ 1,000 × (Wh / 1,000 トークン) ÷ 1,000
水 L  = kWh × (施設内 WUE [L/kWh] + 発電側 [L/kWh])
世界 トークン/秒 = (Google 1.3 × 10^15 /月 + Microsoft 5 × 10^14 /年) × 倍率 = 5.1 億 × 倍率
平均電力 W = トークン/秒 × (Wh/1,000 トークン ÷ 1,000) × 3,600
開いてからの累計 = 経過秒 × 毎秒の量（足し込まない）
```

## モデルの級（`MODEL_CLASSES`、例は 2026-10 時点）

| 級 | Wh / 1,000 tok | 例 | 根拠 |
|---|---|---|---|
| 軽量・高速 | 0.3 | Gemini 3.8 Flash / 3.5 Flash-Lite、Claude Haiku 5.5、GPT-6 Luna / Instant、DeepSeek V4.1 Flash | G1、MR1 の四分位下 |
| 標準 | 1.0 | Claude Sonnet 5.5、GPT-6 Sol / 6.1 Sol、Gemini 3.1 Pro、Kimi K3 | MR1 中央値 0.31 Wh ≈ 300 tok、O1、V1 |
| 最上位 | 3.0 | Claude Opus 5.5 / Fable 5.1、GPT-6 Astra、Gemini 4 Argon、Muse Wonder | MR1 の四分位上 × 大型係数、J1 |
| 研究推計の上限 | 18 | GPT-5 の 1,000 トークン応答推計 | URI1 |

級はモデルの大きさで分ける。推論（思考）はトークン数が増えることで効く（MR1: 15 倍長いクエリで約 13 倍）ので、思考トークンを出力トークンとして数えればよい。

## 境界（何を含むか）

- 事業者の公表値（G1, A1, M1, O1）は施設内の冷却水のみ。学習・発電・ネットワーク・端末は含まない。
- 研究推計（J1, V1, MI1, WP1）は発電側の水や学習の按分を含むことが多い。
- 本アプリは施設内と発電側を分けて持ち、発電側は「中」「高」でだけ足す。

## 実ログの換算（第 3 案）

```
加重トークン = 通常入力 × 1.0 + キャッシュ書き（5 分）× 1.25 + キャッシュ書き（1 時間）× 2.0 + キャッシュ読み × 0.1 + 出力 × 5.0
kWh          = Σ（級ごとの加重トークン ÷ 1,000 × 級の Wh）÷ 1,000 × 前提の幅（低 0.3 / 中 1 / 高 3 倍）
水 L          = kWh × (施設内 WUE + 発電側)          ← 前提ごとの値
キャッシュ無し = 入力・書き・読みをすべて 1.0 として同じ計算（節水 = この差）
```

| 項目 | 値 | 出典 |
|---|---|---|
| 重み | 入力 1.0 / 書き 5 分 1.25 / 書き 1 時間 2.0 / 読み 0.1 / 出力 5.0 | PR1（Anthropic の価格比。価格を計算量の目安とする仮定） |
| モデル ID → 級 | opus / fable / mythos → 最上位、sonnet → 標準、haiku → 軽量、その他 → 標準 | MODELS |
| 重複 | 同じ `message.id` は 1 回だけ数える（1 応答が複数行に記録されるため。生の行を足すと数倍に膨らむ） | `test_weights_and_dedup` |

作例（`src/data/example-usage.json`、仮の数字）: 最上位モデルで 1 日 100 応答、1 応答 = キャッシュ読み 30 万・1 時間書き 8,000・出力 2,500・入力 50 トークン → 加重 586 万トークン、17.6 kWh、水 中 86 L（低 0.79 L / 高 281 L）、500 mL ボトル 171 本。キャッシュが無ければ 469 L。

| ID | 出典 | 使った値 | 注意 |
|---|---|---|---|
| PR1 | Anthropic「Prompt caching」/ 価格（2026-10） | 読み 0.1 倍、5 分書き 1.25 倍、1 時間書き 2 倍、出力は入力の 5 倍 | 価格を計算量の目安として使うのは本アプリの仮定 |

## 映像と「手で注ぐ」に使う作例（`src/data/example-usage.json`）

**利用者本人の利用量はリポジトリに入れない**（public のため）。映像と静的配信の「応答 1 回ぶん注ぐ」は、次の作例（仮の数字）から `usageWater()` で計算する。結果はファイルに書かない。

| 項目 | 値 |
|---|---|
| 想定 | 最上位モデルの Claude Code を 1 日使い込む。1 日 100 応答 |
| 1 応答の内訳 | キャッシュ読み 30 万、1 時間書き 8,000、出力 2,500、通常入力 50 トークン |
| 1 応答 | 加重 58,550 トークン → 176 Wh（最上位 3 Wh/1,000）→ 0.86 L（中: 0.375 + 4.5 L/kWh）= 500 mL ボトル 1.7 本 |
| 1 日 | 中 86 L（低 0.79 L / 高 281 L）、ボトル 171 本、キャッシュ無しなら 469 L |

器（`params.json` の `vessels`、実寸 m）: 500 mL ボトル（幅 0.065・高さ 0.21）、浴槽（1.6 × 0.6、200 L）、25 m プール（25 × 1.2、奥行 13、39 万 L）、東京ドーム（幅 244・高さ 56、12.4 億 L）。
量に合う器は「個数が上限（ボトル 300 / 浴槽 60 / プール 60 / ドーム 30）に収まる最初の器」。世界の 1 日（中 4.3 億 L）は東京ドーム 0.35 杯。
