# 既知課題と確認事項

Phase P（プロンプト生成ツールへの作り替え）で、課題の顔ぶれが大きく入れ替わった。
描画・レイアウト・テンプレート推定・着せ替えに関する旧 #1〜#23 は、その機能ごと無くなったので閉じている
（履歴は `docs/99` と git を参照）。

## 現在の課題

| # | 課題 | 影響 | 対処・回避 |
|---|---|---|---|
| 24 | **SVG・canvas で描かれた HTML 図解を取り込めない** | AI が作った図解の多くは SVG。その図が仕様に載らない | 未対応。`div` ベースのカード・グリッドなら図形として読める。**次に手当てすべき筆頭**（Phase O として計画済み） |
| 25 | Mermaid 記法（```mermaid / `<pre class="mermaid">`）は文字として読まれる | 図解ではなく本文の一部として仕様に入る | 未対応。#24 と同じ段で扱う |
| 26 | 型の推定は規則ベース | 外れることがある | **外れる前提**。判定理由を必ず出し、画面の表で直せるようにしている（`CLAUDE.md` 9 章）。規則を増やして精度で殴らない |
| 27 | 出来上がりの品質は Copilot 次第 | 同じプロンプトでも結果が揺れる | このアプリは指示文の質までしか責任を持てない。型ごとの作り方を必ず書き、枚数と文言を固定して揺れを減らす。**実機確認（`docs/04` 7 章 E1・E2）でしか確かめられない** |
| 28 | 外部 CSS を読み込むテーマは配色が取れない | 「色が 1 つも出ない」 | `THEME_EXTERNAL_CSS` で理由を出し、その CSS を `<style>` に貼ってから読ませるよう促す |
| 29 | 複数のスライドマスターを持つ PowerPoint は 1 個目の配色だけを使う | 2 個目以降の配色が反映されない | `THEME_MULTIPLE_MASTERS` で明示する |
| 30 | プロンプトの長さに上限がある（既定 12,000 字） | 長い資料は後ろの頁が外れる | `PROMPT_TRUNCATED` で外した枚数を出す。分けて渡す運用 |
| 31 | 解析結果はサーバーのメモリに最大 8 件しか残らない | 時間を置くと「もう一度投入してください」になる | 手元で 1 人が使う前提の割り切り。投入し直せば済む |
| 32 | PowerPoint の SmartArt・動画・マクロは読み取れない | その部分が仕様に載らない | 未対応要素として枠だけ残す |
