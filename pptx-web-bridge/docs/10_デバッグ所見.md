# デバッグ所見（境界入力の探索結果と判断）

2026-09-09。API に 50 種類の境界入力（空 HTML、壊れた data URI、巨大表、10 列グリッド、5000 字段落、script 混入、Shift_JIS、ZIP に HTML 無し、拡張子偽装、PPTX 0 枚、未入力プレースホルダ、グラフ、2 階層グループ、負座標・範囲外、巨大数値 JSON、型不正 JSON、パストラバーサル、未知モード など）を通し、例外・不整合・警告を洗い出した。

## 結論
- **クラッシュ（500）は 0 件**。すべて 200/404/422 で返り、失敗工程名がメッセージに入る。
- **決定性**: 同一入力からの JSON は完全一致。JSON の書き出し → 再投入も一致。
- **編集の反映**: 題名編集 → PPTX → 再読込で反映を確認。
- **安全性**: プロジェクト名のパストラバーサルは正規化され、静的ファイルの上位参照は 404。取込 HTML の `<script>` / `onclick` / `javascript:` はテキストとして扱われ、Web 出力ではエスケープされる。

## 見つけて直したもの（第 4 版）
| # | 症状 | 原因 | 対処 |
|---|---|---|---|
| 1 | 10 枚以上のカードが 1 列に縦積みされ 4 枚に分割 | グリッド判定が「子要素 2〜6 個」に固定 | 個数上限を撤廃し、`max_columns` で折り返す |
| 2 | 巨大座標（1e308）の JSON が出力時に要素単位で失敗 | 修復が数値範囲を見ていない | 修復でキャンバスの 2 倍に丸め `BBOX_CLAMPED`。size_pt は 0〜400 の範囲外を無効化 |
| 3 | `runs` が文字列、段落が文字列、セルが数値の JSON がスキーマ違反のまま残る | 修復が型を強制していない | 段落・ラン・セルを型強制（文字列は 1 ランに、数値は文字列化）`PARAGRAPH_FIXED` / `TABLE_FIXED` |
| 4 | 60 行の表が切り詰められる（`ELEMENT_TRUNCATED`） | 表の分割規則が無かった | 行単位で次スライドへ送り、ヘッダー行を続きにも付ける |
| 5 | 5000 字の 1 段落が切り詰められる | 段落単位でしか分割しない | 文の切れ目（。．!?）で複数段落へ分け、切れ目が無ければ文字数で切る |
| 6 | 未入力プレースホルダや空のテキストボックスが要素として残る | 文字の有無を見ていない | 文字も塗りも無いテキストボックスは出力しない |
| 7 | 空 HTML で警告なしの 0 枚 | 本文なし判定が section 経路を通らない | `NO_CONTENT` 警告を必ず出す |
| 8 | PPTX を HTML として投入すると「ZIP 内に HTML が無い」 | 形式判定が無い | 「これは PPTX のようです」「これは HTML のようです」と案内 |
| 9 | 未知の出力モードが黙って editable になる | 警告なし | `MODE_UNKNOWN` 警告 |
| 10 | 入力起因の 422 でもスタックトレースがログに出る | 例外種別を区別していない | ValueError / BadZipFile は WARNING 1 行、それ以外は従来どおり exception |

## 見送ったもの（現状の判断）
- 同一 ID の重複を修復で振り直すこと: 編集 UI の複製で ID が一意になるよう既に対策済み。品質検査 `DUPLICATE_ELEMENT_ID` で検知できるため、自動で振り直すと参照が壊れる恐れがあり見送り。
- 0 枚の資料の出力を拒否すること: 空の Web / PPTX を作れる方が「空の資料を作る」導線と整合するため許可のまま。
- 表セル内の文字あふれ検査: セル単位の推定は行高が動的で誤検知が多いため未実装（既知課題へ）。

## 「この状態で良いか」の判断
- 業務利用の入口（PPTX → Web、HTML → PPTX、JSON 保存・復元、テンプレート適用、要素一覧）は、想定した境界入力で停止せず、警告で状況が分かる。**社内の試用に出せる状態**と判断する。
- 残るリスクは環境依存（PowerPoint 実機表示、フォント差）と、画像内文字（OCR 未接続）。これは Issue #7 と既知課題に残す。
