| サブタイトル | text, role=subtitle | |

| ノート | slide.notes | |
| 単色背景 | slide.background.color | グラデーション・画像背景は無視 |

## 4. 自動レイアウト（`backend/app/layout.py`）
- 余白 36pt、間隔 18pt、題名高さ 64pt（設定）。
- 文字サイズを `typography.py` で正規化してから配置する（帯域クランプと `font_pt` の確定）。
- 題名 → 本文の順に上から積む。`layout_hint.columns` を持つ連続要素は列に分ける。`layout_hint.row` を持つ連続要素（本文＋画像＋キャプション）は横並びの 1 行にし、画像側の幅は `layout.image_side_weight`（既定 0.4）。
- 画像は実寸（px×0.75）と縦横比を保つ。高さの上限は `layout.image_max_height_ratio`×キャンバス高、残り高さが `layout.image_min_height_pt` を下回るなら縮めずに次ページへ送る。列内・全幅とも左右中央。
- PPTX 由来で座標を持つ要素（固定）と持たない要素（流し込み）が混在する場合、固定要素が占めない最大の空き帯へ流し込む。続きページには固定の題名を「（続き）」付きで複製する。
- 画像は幅いっぱいを基準に、残り高さに収まらなければ縦横比を保って縮小し中央寄せ。残りが 35% 未満なら次ページ。
- 収まらないときは、まず本文全体（列・横並びが無い場合）または要素単位で `layout.autofit_steps`（1.0 → 0.85）の順に文字を縮め、収まれば `font_scale` に記録して分割しない。残り高さが `layout.split_min_remaining_ratio`（本文領域の 25%）未満なら分割せず要素ごと次ページへ送る。`keep_with_next` の見出しはページ末尾に残さない。
- それでも収まらない本文は段落単位で分割し、次スライドの題名に「（続き）」を付け、`continuation_of` / `continuation_index` を記録する（`SLIDE_SPLIT`）。1 段落で収まらない場合は文の切れ目で分ける。表は行単位で分割し、ヘッダー行を続きにも付ける。
- 1 要素で 1 枚に収まらない場合は高さを切り詰めて `ELEMENT_TRUNCATED`。

## 5.1 PPTX からテンプレートを推定する（`backend/app/template_from_pptx.py`）
表紙・中身・最終ページの小さな PPTX を読み、`config/templates.json` と同じ形の部品定義を提案する。UI（「PPTX からテンプレート作成」）で枠を直してから保存する。

| PPTX の要素 | 判定 | テンプレート部品 |
|---|---|---|
| スライドの役割 | 先頭 = 表紙、末尾 = 最終ページ（3 枚以上、または 2 枚で末尾の文字が 40 字未満）、残り = 中身 | `cover` / `content` / `closing`（UI で上書き可、「使わない」も可） |
| 図形の収集 | スライド本体 → レイアウト → マスター（`showMasterSp=0` ならマスターは見ない）。グループは平坦化。題名・副題・本文プレースホルダはレイアウトのものも位置の手がかりに使うが、フッター・日付・ページ番号はスライド本体に置かれたものだけ | 各部品に `source: slide / layout / master` |
| 画像（面積 80% 以上） | 背景画像 | `background_image` |
| 画像（幅 25% 以下で端から 15% 以内。最終ページは幅 50% 以下） | ロゴ（各部品 1 つ、高さは縦横比から） | `logo {image, x, y, w}` |
| その他の画像 | 装飾画像（最大 6） | `images[]` |
| 文字の無い塗り図形・線（面積 80% 未満） | 帯。平行四辺形は `adj × min(w, h)` を傾きに | `bar`（最大のもの）と `bars[]` |
| 文字の無い塗り図形（面積 80% 以上）/ 背景の単色・画像 | 背景 | `background_color` / `background_image` |
| 題名・副題・本文プレースホルダ | 位置と先頭 run の書式（継承を含む） | `title` / `subtitle` / `body`（本文領域） |
| 下部 15% の小さな文字 | ページ番号フィールド（`a:fld slidenum`）・数字だけ・「n / m」→ ページ番号。それ以外はフッター（日付は `{date}` に置換し `date_format` を推定） | `page_number` / `footer` |
| 最終ページの文字 | 一言（中央揃え） | `message` |
| テーマ | `a:clrScheme`（accent1 → primary、dk2 → secondary、lt1 → background、dk1 → text …）と `a:fontScheme`（ea → latin） | `colors` / `fonts` |
| 元ファイル | `config/template_assets/user/<id>/base.pptx` に保存 | `base_pptx`（土台出力に使う） |

保存先: 定義は `config/user_templates.json`、画像は `config/template_assets/user/<id>/`（exe 版は exe の隣）。組込テンプレートと同じ ID は使えない。

## 5.2 Copilot 連携（`backend/app/copilot_handoff.py`、API 不使用）
文章と構成だけを Copilot に渡し、座標・ブランド部品はこのアプリと PowerPoint のブランドキットが受け持つ。受け渡しはクリップボード・ファイル・貼り付けだけで行う。

| 方向 | 形式 | 内容 |
|---|---|---|
| 渡す | Markdown（`outline.md`） | `# 資料題名`、`## n. スライド題名`、`型: 表紙 / 最終ページ`、箇条書き（レベルは 2 字下げ）、`*副題*`、表（Markdown 表）、`画像: ファイル名（代替文）`、`ノート: …` |
| 渡す | 簡易 JSON（`outline.json`） | `{title, brand{colors, fonts}, slides[{n, title, layout, bullets[{text, level, role}], tables, images, notes}]}` |
| 渡す | Word（`outline.docx`） | 見出し 1 = スライド、箇条書き、表、ノート段落。python-docx を使わず最小の WordprocessingML を書く。Copilot in PowerPoint の「ファイルから作成」用 |
| 渡す | プロンプト | `config/copilot_prompts.json` の用途プリセット（ブランドスライド化 / 図解風 / 要約 / 発表者ノート / 翻訳 / JSON）。`{title} {slides} {count} {language} {brand}` を置換 |
| 戻す | Markdown | 見出しごとに `<section>` を持つ HTML に変換してから `html_parser` を通す（実装を二重にしない）。`型: カード / フロー / 比較 / 数値 / 年表` は図解要素にし（4.5）、`型: 表紙` は表紙にし、`ノート:` はノートへ |
| 戻す | 簡易 JSON | 上の形式をそのまま Presentation JSON へ（`layout` は語で指定してもよい: カード / 比較 / 表 …） |
| 戻す | ノートだけ | `## n.` の番号（無ければ順番）で既存スライドのノートへ入れる |

## 4.5 図解部品（`backend/app/diagrams.py`）
箇条書きだけでは伝わらない内容を「型 + 項目」で持ち、描画・PPTX 出力の直前に既存のプリミティブへ展開する。要素は `type: "diagram"` の 1 つで、子要素は保存しない（編集は型と項目だけを触る）。

| 型 | 見え方 | 項目数 | Copilot の語 | Markdown の書き方 |
|---|---|---|---|---|
| `flow` | 角丸の箱 → 矢印 → 箱 | 2〜6 | フロー / 手順 / 流れ / ステップ | `- 受付: 窓口で受け取る` |
| `cards` | カードを横並び（4 つ以上は 2 段） | 2〜6 | カード / 要点 / 3分割 | `- 見出し: 説明` |
| `compare` | 左右 2 枠（見出し帯 + 本文） | 2 | 比較 / Before / 対比 | `- Before: 二重作業` |
| `kpi` | 大きな数値 + ラベル | 1〜4 | KPI / 数値 / 指標 | `- 40%｜作業時間の削減` |
| `timeline` | 横線 + 丸 + 時点ラベル | 2〜6 | 年表 / タイムライン / 沿革 | `- 2024: 試験導入` |

- 色はテンプレートの `primary` / `accent` / `surface` / `line` を使う。項目が 4 つ以上になると文字を自動で縮める（Phase A の `font_scale` と同じ 0.5〜1.0）。
- レイアウトでは分割しない。高さは本文幅に対する比（`diagrams.TYPES[].height_ratio`）で決め、`layout.diagram_max_height_ratio`(0.55) × キャンバス高で頭打ち。空きが `layout.diagram_min_height_pt`(140) 未満なら次ページへ送る。
- PPTX へは子図形として書き出し、図形名を `diagram:<型>:<要素 id>:<連番>` にする。再読込時に同じ名前の図形をまとめて 1 つの図解へ戻す（戻せない場合は個別図形のまま残す）。
- Copilot とは `型:` の 1 語でやり取りする（上の表の語）。回答の箇条書きは `見出し: 説明`、数値は `値｜ラベル`。下位の箇条書きは 1 つ上の項目の説明に足す。
- 品質検査: `DIAGRAM_TOO_MANY_ITEMS`（項目過多）/ `DIAGRAM_TOO_FEW_ITEMS`（情報）/ `DIAGRAM_TOO_SMALL`（枠が低すぎる）。
- HTML 取込から自動で図解にはしない（HTML 側に型の手がかりが無いため）。図解は「図解を追加」か Copilot の回答から作る。

## 5.3 Copilot エージェント一式（`backend/app/copilot_agent_kit.py`、API 不使用）
上の書式（5.2）を Copilot 側にも覚えさせるための書き出し。ZIP を保存し、Copilot Studio（エージェントビルダー）や宣言型エージェントの素材として手で登録する。アプリから Copilot を呼ぶことはない。

| ファイル | 内容 |
|---|---|
| `declarativeAgent.json` | 宣言型エージェントの定義。`instructions` は `$[file('instructions.md')]` を指す。`conversation_starters` は用途プリセット（最大 `agent.starters_max` 件）から作る。読み込めない環境では下の指示文を手で貼れば同じ働きをする |
| `instructions.md` | エージェントへの指示文。役割（文章と構成だけを扱い、体裁はアプリが決める）、返し方（Markdown 契約を崩さない・前置きを書かない）、型の選び方、テンプレートの配色（16 進数）、用途の一覧、機密の注意 |
| `knowledge/M365AgentContext_INDEX.txt` + `_001.txt …` | ナレッジとして添付するテキスト。1 ファイル 30,000 字・本文 19 ファイルまで（目次と合わせて M365 Copilot の 20 ファイル上限に収める）。中身は Markdown 契約 / 簡易 JSON の形 / 用途別の依頼文 / テンプレートの配色・フォント・部品（図解の型は Phase F で追加） |
| `kit.json` | 上の元になった記録（`file_name` / `summary` / `text`）。別の詰め替え（crossai-packager など）に渡せる形 |
| `READ_ME.txt` | 登録手順と注意 |

知識の中身は設定とコードから組み立てるため、文書ファイルが無い exe 版でも同じものが出る。テンプレートを選んでから書き出すと、そのテンプレートの配色が知識と指示文に入る。

## 5.4 差分マージ再取込（`backend/app/merge.py`）
同じ資料を直して取り込み直すとき、キャンバスで直した座標・文字・ノートを残したまま、変わったところだけを反映する。3 方向マージ（base = 前回の取込記録 / ours = いまの資料 / theirs = 新しい取込）。

| 状況 | 採用 | 記録 |
|---|---|---|
| 取込側が変わっていない | 今の資料（編集を保持） | `kept_edits` |
| 取込側が変わり、自分は未編集 | 取り込んだ内容 | `updated` |
| 両方が変わった | 既定は取り込んだ内容の文言 ＋ 自分の座標・書式（`conflict=ours` で自分の文言） | `conflicts[]` |
| 取込側で消えた | 自分が編集していれば残す、していなければ消す | `kept_deleted` / `removed` |
| 取込側で増えた | 追加（座標が無いので自動配置される） | `added` |
| 自分が足した要素・スライド | そのまま残す | `kept_edits` / — |

- 対応付けは id ではなく鍵で行う（id は取込のたびに振り直される連番のため）。優先順は ①取込時の鍵（`import_key`）の一致 → ②前回記録の同じ位置の鍵 → ③内容の鍵 → ④文字が 6 割以上似ている同種の要素。
- スライドの並びは取り込んだ側を正とし、自分が足したスライドは末尾に残す。ノート・背景・テーマは「前回から自分が変えていれば自分のもの」。
- 座標は常に `user_bbox`（手で動かした枠）を優先する。
- 入口: `POST /api/import/merge`（PPTX / HTML / ZIP / JSON / Markdown）、Copilot の回答は `POST /api/copilot/import` の `apply=merge`。UI は同じ形式のファイルを投入したときに「差分を取り込む / まるごと置き換える」を尋ねる。

## 6. フォント
- `config/font_fallback.json` の `aliases` で置換。Web は `web_font_stack`、PPTX は候補の先頭を指定。
- 実際の有無は表示側（ブラウザ / PowerPoint）で解決されるため、環境差はここで吸収する。
