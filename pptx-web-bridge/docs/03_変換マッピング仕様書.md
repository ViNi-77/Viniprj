# 読み取りとプロンプト生成の仕様

このアプリは図解を描かない。**読み取って、Copilot への指示文にする**だけ。
本書はその 2 段の規則を書く。

```
投入ファイル ──▶ Presentation JSON ──▶ 図解仕様（何が書いてあるか）──┐
             └─▶ テーマ（どんな見た目か）──────────────────────────┴──▶ プロンプト
```

---

## 1. 図解仕様（`backend/app/spec_builder.py`）

Presentation JSON から、**文章と構造を分けた** AI 向けのデータを作る。画面にもこれを出す。

```yaml
資料: 受注から出荷までの流れ
出典: diagram.html
枚数: 2
ページ:
  - 番号: 1
    題名: 受注から出荷までの流れ
    型: フロー（手順・流れ）
    リード: 現行プロセスの全体像
    項目:
      - 見出し: ① 受注
      - 見出し: ② 在庫引当
  - 番号: 2
    題名: ボトルネック
    型: 数値（指標を大きく見せる）
    箇条書き:
      - 転記に 1 件あたり 5 分
```

### 1.1 型と、当て方

| 型 | 意味 | 当て方（上から順に見て、最初に当たったものを採る） |
|---|---|---|
| `flow` | フロー（手順・流れ） | 横並びの枠に矢印（→ ⇒ ▶）か連番（①②/1./STEP1）が付く |
| `cards` | カード（要点を並べる） | 同じくらいの大きさの枠が 2 つ以上並ぶ |
| `compare` | 比較（Before / After） | 枠がちょうど 2 つで、対の言葉（Before / After / 導入前 / 改善後…）が入る |
| `kpi` | 数値 | 本文の過半数の行が「数字 + 単位」で出来ている |
| `timeline` | 年表 | 本文に西暦が 2 つ以上ある |
| `table` | 表 | 表がある |
| `bullets` | 箇条書き | 本文の行がある |
| `image_text` / `image` | 画像 + 説明 / 画像だけ | 画像があり、本文があるか無いか |
| `title_only` | 題名だけ | それ以外に中身が無い |

先に**題名に型の名前が書かれていないか**を見る（「申請のフロー」→ フロー）。一番外れにくい手掛かりのため。
型の語彙は `diagrams.TYPES` が正で、画面の選択肢もプロンプトの言葉もそこだけを見る。

**推定は必ず外れる前提**（`CLAUDE.md` 9 章）。だから:

- 判定理由（`kind_reason`）を必ず添える（「横並びの枠が 3 個あり、矢印か番号が付いている」）
- 画面の表で型を変えられる（`kind_overrides`）。変えたものは理由が「画面で指定された」になる
- 精度を上げるために規則を増やし続けない

### 1.2 中身の取り出し

| 仕様のキー | 元 | 注意 |
|---|---|---|
| `title` | `slide.title` → 役割 title の要素 → 先頭の文字 | |
| `lead` | **1 行だけ**の副題・キャプション | 複数行のものはリードではなく中身。ここを雑にすると、見出し直後の箇条書きが丸ごと消える |
| `items` | 横並びの枠。1 行目を見出し、残りを説明に分ける | |
| `bullets` | 題名とリード以外の文字 | 役割名ではなく「リードに使ったか」で分ける |
| `table` | 表（見出し行を分離） | |
| `images` | 画像（ファイル名・代替文・実体があるか） | 実体は仕様に入れない。一式 ZIP へ |
| `notes` | 発表者ノート | |

**文言は一字も変えない。** 要約・言い換え・並べ替えは Copilot の仕事であって、この変換の仕事ではない。
中身が 1 つも取れない頁は `SLIDE_HAS_NO_CONTENT` を出す（黙って流さない）。

### 1.3 見た目は仕様に入れない

`to_yaml()` は配色・フォントを書かない。見た目を語る場所はプロンプトのテーマ欄 1 か所だけにする。
2 か所に書くと必ず食い違う。

## 2. 見た目（テーマ）

`theme_from_html` と `theme_from_pptx` は**同じ形**を返す。プロンプト側が入力の種類を気にしないため。

```
{name, filename, colors: {background, text, heading, card, line, muted, accent},
 fonts: {heading, body}, decoration: {radius_px, padding_px, shadow, border},
 kinds: [...], palette: [...], sources: {...}, warnings: [...]}
```

### 2.1 HTML 図解テーマ（`theme_from_html.py`）

| 段 | 規則 |
|---|---|
| 集める | `<style>` の中身と、要素の `style=` 属性だけ。**外部 CSS は取りに行かない**（`THEME_EXTERNAL_CSS` を出す） |
| CSS 変数 | `:root { --brand: #... }` を先に解決する。AI が書く HTML で一番多い書き方で、飛ばすと色が 1 つも取れない |
| 役割 | セレクタから当てる（背景 = `body` の background、見出し = `h1/h2/h3` の color、カード = `.card/.panel/.box`…） |
| 当たらないとき | 色そのものの性質で埋める（一番明るい色 = 背景、一番暗い色 = 文字、一番鮮やかな色 = アクセント） |
| 根拠 | どちらで決めたかを `sources` に残す |
| 装飾 | `.card` 系の `border-radius` / `padding`、`box-shadow` と `border` の有無 |
| 型 | `spec_builder.infer_kind` を使い回す（テーマも結局 HTML 図解なので、判定を二重に持たない） |

### 2.2 PowerPoint（`theme_from_pptx.py`）

スライドマスターの `a:clrScheme` / `a:fontScheme` から読む（Phase K〜N で作った `pptx_styles.ThemeInfo` を使う）。

| 役割 | 元 |
|---|---|
| 背景 / 文字 | `lt1` / `dk1` |
| 見出し | `accent1`（無ければ `dk2`） |
| アクセント | `accent2`（無ければ `accent1`） |
| 枠線 / 補足 | `lt2` を暗く / `dk1` を明るく |
| フォント | `major_ea`（無ければ `major_latin`） / `minor_ea` |

**`presentation["theme"]` は使わない。** あれはアプリ既定のテンプレート色であって、実ファイルの色ではない。

## 3. プロンプト（`backend/app/prompt_builder.py`）

| 向き | 入力 | 貼り先 | 出来上がるもの |
|---|---|---|---|
| `to_pptx` | HTML 図解（+ テーマ） | Copilot in PowerPoint | 会社様式の PowerPoint |
| `to_html` | PowerPoint | ふつうの Copilot チャット | 1 ファイルの HTML 図解 |

プロンプトの組み立て:

1. **何を作るか**（枚数を明示。「増やさない・減らさない」）
2. **文言は一字も変えない**
3. **その資料に出てくる型だけ**、作り方を書く（使わない型の説明で薄めない）
   - 例 `to_pptx` のフロー: 「左から右へ同じ大きさの箱を並べ、箱と箱の間を矢印でつなぐ」
   - 例 `to_html` のフロー: 「横並びの flex に箱を置き、間に矢印（→）を入れる」
4. ノートの扱い（PowerPoint は発表者ノート / HTML は HTML コメント）
5. 画像があれば「そのファイル名の枠を作る」（実体は一式 ZIP で添付）
6. 見た目（テーマがあるときだけ。無ければ**色を勝手に決めない**）
7. 図解仕様の YAML

`to_html` では **CDN・外部ファイル・JavaScript を使わない**よう明記する（この環境では CDN が塞がれており、
出来た HTML をそのまま読み込ませたときに壊れるため）。

長さの上限（既定 12,000 字、`config/app_config.json` の `copilot.max_prompt_chars`）を超えると
後ろの頁から外し、`PROMPT_TRUNCATED` で**何枚外したかを必ず言う**。

## 4. 受け渡し一式（`backend/app/handoff_pack.py`）

| ファイル | 中身 |
|---|---|
| `はじめにお読みください.txt` | 手順・添付する画像の数・読み取れなかったもの |
| `プロンプト.txt` | 貼り付けるもの |
| `図解仕様.yaml` | 読み取った中身 |
| `構成.docx` | Copilot in PowerPoint の「ファイルから作成」用。python-docx を使わず最小の WordprocessingML を自前で書く（exe の同梱物を増やさないため） |
| `画像/` | 資料に入っていた画像 |

Word は**図解仕様から**組み立てる。Presentation JSON から直接作ると「画面に出ているものと渡すものが違う」が起きる。

---

## 5. 読み取れないもの

黙って消さず、必ず警告として画面に出す。

| 入力 | 読み取れないもの | 警告 |
|---|---|---|
| HTML | SVG・canvas で描いた図 | （未対応。`docs/07` #24） |
| HTML | 外部 CSS ファイル | `THEME_EXTERNAL_CSS` |
| HTML | 外部 URL の画像 | `REMOTE_IMAGE_SKIPPED` |
| PowerPoint | SmartArt の内部構造・動画・マクロ | 未対応要素として枠だけ残す |
| 共通 | 中身の無い頁 | `SLIDE_HAS_NO_CONTENT` |
