# 受入試験仕様書（草案）

企画書 7 章の受入条件と、8 章のリスク対策を試験項目に落とした。自動化されているものは試験名を併記する。

| # | 受入条件（企画書 7 章） | 試験手順 | 合格基準 | 自動化 | 状態 |
|---|---|---|---|---|---|
| 1 | Windows 上でローカル Web 画面が起動する | `start_windows.bat` または exe を実行 | ブラウザに UI が表示され、`/api/health` が `{"ok": true}` | `tests/test_api.py::test_config_and_health`（API 部分） | CI（Windows ランナー）の起動スモークテストで確認済み |
| 2 | PPTX を D&D またはファイル選択で投入できる | サンプル PPTX を投入 | スライド一覧に 6 枚が並び警告 0 | Playwright による UI 操作（手順は README） | 確認済み |

| 11 | 要件、README、コード、試験結果の版が一致する | `docs/試験結果.md` の日時と `git log` を照合 | E2E を再実行すると試験結果が更新される | `scripts/run_e2e.py` | 合格 |

## 追加試験（リスク対策）
| 項目 | 手順 | 合格基準 | 自動化 |
|---|---|---|---|
| 文字切れ検出 | 小さな枠に長文を置いた JSON を検査 | `TEXT_OVERFLOW` が出る | `test_text_overflow_detected` |
| 重なり検出 | 重なる 2 要素 | `ELEMENT_OVERLAP` | `test_overlap_detected` |
| ページ順 | index が並び順と異なる JSON | `SLIDE_INDEX_MISMATCH` | `test_out_of_canvas_and_index` |
| 長文の分割 | 30 段落の本文 | 2 枚以上に分割され「（続き）」 | `test_split_when_too_much_text` |
| 壊れた JSON の修復 | 欠落だらけの JSON を反映 | 修復警告付きで有効な JSON になる | `test_repair_fixes_missing_fields` |
| 見た目優先のフォールバック | Playwright 未導入環境で visual を選ぶ | `VISUAL_MODE_UNAVAILABLE` 警告で editable 出力、文字はテキストのまま | `test_visual_mode_falls_back_to_editable_when_raster_unavailable`, `test_hybrid_without_raster_uses_boxes`（Issue #11） |
| 4:3 資料 | 4:3 PPTX を投入 | `ASPECT_NOT_16_9` 警告、比率維持、テンプレート部品も拡縮 | `test_4_3_deck_keeps_ratio_and_warns`（Issue #11） |
| 上限超過・大容量 | 上限超のファイル投入、120 枚 × 20 段落の JSON | 413 を返す。レイアウトと品質検査が 60 秒以内に完走 | `test_upload_limit_returns_413`, `test_large_presentation_layout_completes`（Issue #11） |

## PPTX からテンプレート作成の試験（Phase C）
| 項目 | 手順 | 合格基準 | 自動化 |
|---|---|---|---|
