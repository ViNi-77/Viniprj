# 要件定義書（Phase P 改訂）

> Phase P で目的そのものが変わった。旧版（PowerPoint ⇄ Web 図解をアプリ自身が変換する）は
> `docs/99` 2026-09-14 の判断で置き換えられている。履歴は git を参照。

## 1. 目的と利用者

- **目的**: PowerPoint や HTML 図解を読み取り、**Copilot がそのまま実行できる指示文（プロンプト）を作る**。
  図解を描くのは Copilot であって、このアプリではない。
- **利用者**: 非エンジニアの資料作成者。ブラウザ操作だけで、投入 → 確認 → コピーまで完結する。
- **実行環境**: Windows のローカルアプリ（ブラウザ UI + ローカル API）。exe 版はダブルクリックで起動。

## 2. 解決したい困りごと

| # | 困りごと | このアプリの答え |
|---|---|---|
| 1 | Web 図解で作った資料を PowerPoint にするとき、レイアウトも会社の体裁も 1 から作り直しになる | 中身と見た目を読み取り、Copilot in PowerPoint への指示文にする |
| 2 | 難解な PowerPoint を Web 図解にしたいが、どう落とし込むか迷う | 中身を読み取り、Copilot チャットへの「HTML 図解を作れ」という指示文にする |
| 3 | AI に「いい感じに図解して」と頼むと毎回違うものが出る | 頁ごとの型と、型ごとの作り方を指示文に必ず書く |
| 4 | 社外秘の資料を外部サービスに出せない | 解析はすべて手元。外部送信なし。貼り付け先は利用者が選ぶ |

## 3. 画面（1 本道）

| 段 | 機能 |
|---|---|
| 1. 資料を投入する | D&D かファイル選択で PowerPoint（`.pptx`）/ HTML 図解（`.html` / 画像入り `.zip`） |
| 2. 読み取った中身を確かめる | 頁ごとの題名・型・**判定理由**・中身の要約を表で出す。型はその場で変えられる。図解仕様（YAML）も見られる |
| 3. 見た目を決める | 元ファイルの配色を使う / HTML 図解テーマを読み込んで差し替える / 指示しない |
| 4. Copilot に渡す | 向き（PowerPoint 化 / HTML 図解化）を選び、プロンプトをコピーするか一式（ZIP）をダウンロード |
| 読み取れなかったもの | 落とした要素と理由を必ず出す（黙って消さない） |

## 4. 機能要件

| # | 要件 |
|---|---|
| F1 | PowerPoint から題名・本文・箇条書き・表・画像・図形の文字・ノートを読み取る |
| F2 | HTML 図解から見出し・段落・箇条書き・表・画像・カード / グリッドを読み取る |
| F3 | 頁ごとの型を推定し、**判定理由を添えて**画面で変えられるようにする |
| F4 | PowerPoint のテーマ色・フォントを**実ファイルから**読む |
| F5 | HTML 図解テーマの配色・フォント・角丸を読む（CSS 変数を解決する） |
| F6 | 2 つの向きのプロンプトを組み立てる。文言は一字も変えない |
| F7 | プロンプト・図解仕様・Word 構成・画像を ZIP にまとめる |
| F8 | 読み取れなかったものを警告として画面に出す |

## 5. 非機能要件

| # | 要件 |
|---|---|
| N1 | 資料の中身を外部へ送信しない。解析はすべてローカル |
| N2 | ノート PC（1366×768@125% / 1920×1080@150%）で文字・ボタンが切れず、横スクロールが出ない |
| N3 | Windows で Python 無しに起動できる（exe 配布） |
| N4 | 画面右上のバッジで版とコミットが確認できる（「更新できているか」の唯一の手掛かり） |
| N5 | 外部ライブラリを CDN から読まない（同梱する） |

## 6. やらないこと

- 図解を描かない（PowerPoint も HTML も生成しない）
- 資料を編集する機能を持たない（キャンバス・インスペクタ・並べ替えは Phase P で削除）
- 文章を要約・言い換えしない（それは Copilot に頼むもの）
- Copilot の API を使わない（コピーと貼り付けで受け渡す）
