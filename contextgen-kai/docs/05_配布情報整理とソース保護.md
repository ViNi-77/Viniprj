# 利用者向け配布の情報整理とソース保護

文書版0.1 / 対象アプリ0.2.1 / 2026-09-23 / 実装済み項目と判断待ち項目を区別

## 配布の前提

配布者がソースを管理し、利用者はZIPだけを受け取る。利用者の開始点はZIPの「すべて展開」とEXEのダブルクリック。Gitの取得・更新手順と設計文書は配布者向けREADMEとソース側へ残す。

## 利用者に不要な情報の候補と扱い

| 候補 | 利用者ZIPでの扱い | 配布者側での扱い |
|---|---|---|
| Git clone/pull、ブランチ名、リポジトリURL、起動・更新BAT | 除外。新しいZIPを受け取る手順へ変更 | README・Git管理に保持 |
| Python/仮想環境/pip、ビルド操作、依存定義、試験コード | 説明とソースを除外。必要な実行環境だけ同梱 | ソースで保持 |
| 仕様書兼要件定義書・概要と履歴・基本設計基準書・実装契約 | 配布対象外 | 写真に合わせたソース直下の配置を維持 |
| Macでの開発・撮影説明、開発端末名、個人の保存パス | マニュアルから除外。Windows上の実操作で画像を更新 | 正確な試験・撮影環境を検証記録に保持 |
| CI実行URL、試験ログ、性能測定JSON、撮影記録 | 配布対象外 | 開発者用の証跡として保持 |
| コミットID・ビルド元・OCR構築手順・ビルドmanifest | 配布対象外 | `build/BUILD-MANIFEST.json` とCI証跡で追跡 |
| `.DS_Store`・`__MACOSX`・`._*`・キャッシュ・デバッグ記号 | 同梱禁止 | 配布検査で混入を拒否 |
| OCR・言語データ・マニュアル画像・画面資源・実行ライブラリ | 必要。`_internal/`へ集約 | ビルド定義で管理 |
| 使用コンポーネントのLICENSE/NOTICE | 必要。`_internal/THIRD_PARTY_LICENSES/`等に保持 | 上流の原文を勝手に削除・改変しない |
| アプリ版・Windows要件・保存先・バックアップと復元 | 必要。利用者向け文書と画面に保持 | 問い合わせと更新の識別に使う |
| OCRの限界・読み取り失敗・修正競合・予約条件 | 必要。利用者向け文書と画面に保持 | 未読や誤読を成功扱いしない |

Mac由来の開発情報を利用者向け配布から外す。過去の開発・検証記録を消去して開発環境を偽ることはしない。第三者ライセンスにあるOS名や著作者名も削除対象にしない。

## 配布フォルダのまとめ方（0.2.1で実装）

```text
ContextgenKai/
├─ ContextgenKai.exe
├─ contextgen改_操作マニュアル.html
├─ 最初にお読みください.txt
└─ _internal/
   ├─ ocr/
   ├─ manual/images/
   ├─ THIRD_PARTY_LICENSES/
   └─ 実行に必要なライブラリ・画面資源
```

利用者が開くファイルを3つに絞り、補助ファイルは1つのフォルダへまとめる。元のPythonソース、設計書、試験、開発用の起動・更新スクリプトを配布しない。Windows用OCR本体と日本語・英語データは引き続きZIPへ含める。ソースをGitで取得する配布者にもOCRは一緒に提供する。

## ソース閲覧対策の選択肢

| 対策 | 得られるもの | 限界・判断 |
|---|---|---|
| 現在のEXE化＋必要ファイルのみ配布 | `.py`を直接開くことを避け、配布フォルダを簡潔にする | EXEに格納されたPythonバイトコードは抽出・解析が可能。画面用HTML/JS/CSSはブラウザから閲覧できる |
| 1ファイルEXE化 | 見える実行ファイル数を減らせる | 起動時に補助ファイルを展開する方式。コード秘匿の対策にはならず、OCRやマニュアルの配布も別途考慮が必要 |
| 非公開の開発リポジトリに分離 | 今後のソース閲覧を許可した人に制限できる | 所有者の判断が必要。公開済みのコピーや履歴を回収することはできない |
| 重要部分のネイティブ拡張へのコンパイル | Pythonバイトコードからの解析を難しくする | Windowsビルドと保守が増える。逆解析を完全に防ぐものではない。未実装 |

**現状確認:** 2026-09-23のGitHub API確認では `ViNi-77/Viniprj` は PUBLIC。ZIP内の整理だけで「ソースを所有者だけが持つ」状態にはならない。既存2プロジェクトへの影響を避けるなら、contextgen 改の開発用リポジトリを別途非公開で管理する案が候補。公開範囲や履歴はこの変更で操作していない。

PyInstallerの仕様根拠: [配布物・ソースコード保護](https://pyinstaller.org/en/stable/operating-mode.html#hiding-the-source-code)。同ページはPythonバイトコードの逆コンパイル可能性と、必要に応じたCythonによるコンパイルを説明している。EXE化を暗号化・完全な閲覧防止と説明しない。
