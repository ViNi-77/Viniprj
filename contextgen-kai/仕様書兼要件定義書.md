# contextgen 改 要件定義書・仕様書

| 文書版 | 対象アプリ版 | 更新日 | 状態 |
|---|---|---|---|
| 0.3 | 0.2.1 | 2026-09-23 | 実装済み・ローカル検証済み・Windows CI検証済み。過去版の実績と実機受入は検証記録で区別 |

## 1. 背景・目的・利用者

部署資料が1万件を超え、どの資料が読めたか、何をCopilotへ渡すか、定期更新が成功したかを確認しにくい。非エンジニアの利用者が、資料の登録→抽出・確認・修正→用途別出力を画面だけで進められるようにする。旧contextgen v3と図解プロンプト作成アプリを維持し、第3の独立アプリとして開発する。

アプリは手元で解析・OCR・索引・出力を行う。生成AIや外部APIは呼ばない。Copilotへの投入と質問回答は利用者が行う。OCRは文字認識であり、図・写真の意味理解を保証しない。

## 2. 機能要件と受入条件

| ID | 要件 | 受入条件 |
|---|---|---|
| FR01 | 複数資料フォルダの登録・単発ファイル投入 | OS選択/パス入力、複数D&D、登録解除で原本を消さない |
| FR02 | 構造と出典を保持した抽出 | Office/PDF/画像/テキスト/CSV/ZIP。出典ページ・シート・スライドを追跡できる |
| FR03 | ローカルOCR | 文字PDFとスキャンの混在、単独画像、Office画像を対象にし、上限・失敗を表示 |
| FR04 | 確認・除外・本文修正 | 原本を書き換えず修正を保持。原本更新時の競合は確認待ち |
| FR05 | 用途別資料セット | フォルダ・検索・個別選択の条件を保存。テーマ名で自動分類しない |
| FR06 | Copilot用出力 | TXT/Markdown/JSONL/出典/抽出結果/健康診断/差替一覧/指示文を出力 |
| FR07 | 複数パッケージ・世代保持 | INDEX+本文19件以内、超過は複数セット。失敗時は前回世代を保持 |

## 3. 画面と操作

ホームで資料の登録、実行、中断、再開と履歴を確認する。資料確認では検索と状態絞り込み、本文修正、収録除外、出典確認を行う。PDF・画像はプレビューし、Office等は原本を標準アプリで開く。出力画面で用途別セットと指示文を設定し、生成・ダウンロード・確認待ちの確定を行う。定期更新・設定で予約、実行履歴、バックアップ、アプリ終了を扱う。

進捗は実処理件数。走査中は総数未確定として件数を表示する。完了、警告、保留、失敗を別状態とする。ブラウザを閉じても本体は残り、終了ボタンで本体を停止する。

## 4. 入出力・データ

入力対象はdocx/xlsx/xlsm/pptx/pptm/pdf/png/jpg/jpeg/webp/tif/tiff/txt/md/csv/tsv/zip。旧doc/xls/pptとOfficeの旧OLE埋め込みは変換案内を返す。マクロは実行しない。暗号化・破損・上限超過の部分を黙って除外しない。

### 初版の処理上限

| 対象 | 上限と扱い |
|---|---|
| 単発取り込み | 1回100ファイル、1ファイル250MiB。大量資料はフォルダ登録を使う |
| 解析する原本 | 1ファイル256MiB、PDFは500ページ。超過・未読部分を警告する |
| ZIP・Office内部 | 1項目64MiB、展開総量512MiB、5,000項目、入れ子3階層、圧縮比2,000倍 |
| 抽出結果 | 原本1件の抽出本文1,000万文字、抽出単位20,000件。超過を黙って切り捨てない |
| 画像 | 4,000万画素。大きすぎる画像は縮小・分割を案内する |
| 時間 | 解析器は原本ごとに60秒の期限を確認。応答しない解析子プロセスは180秒で終了し、次の資料へ進む |
| 同時処理 | 保存領域ごとに走査・抽出・出力は1ジョブ。画面の検索・確認は別処理で受け付ける |

これらはアプリ初版の上限であり、Copilot側の上限ではない。OCR中心の大きな資料は分割して再実行する。

永続化単位は資料フォルダ、文書、抽出単位、修正、用途別セット、ジョブ、処理済みファイル、出力世代、予約。文書の原本ハッシュと修正時ハッシュを比較し、原本が変わった修正を自動で再適用しない。出力の確定は世代ディレクトリを完成させてから有効世代を切り替える。

M365のINDEX/本文には出典を付け、本文最大19ファイルで1セットとする。これは2026-09-23確認の[直接アップロード20ファイル](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/agent-builder-add-knowledge#embedded-file-content)運用に合わせたアプリ設定で、サービス全体の容量上限とは区別する。

## 5. API・実行インターフェース

APIは同梱画面からlocalhostのみで使用。`/api/libraries`、`/api/documents`、`/api/collections`、`/api/jobs`、`/api/exports`、`/api/schedules`をリソースとする。修正には元文書ハッシュを指定し、競合は409を返す。変更操作は起動セッショントークンとOrigin/Hostを検証する。入力形式・API詳細はリポジトリのIMPLEMENTATION_CONTRACT.mdを参照。

CLIは `python -m contextgen_kai`。`--state-dir`、`--port`、`--no-browser`、`--run-schedule`を備え、画面と予約実行で同じジョブ処理を使う。

## 6. 定期更新・障害

毎日・曜日指定・間隔を設定する。アプリ起動中モードとWindowsタスクスケジューラモードを排他的に使う。Windowsでは利用者ログイン中に実行し、PCを起こさない。過去の未実行分は1回にまとめる。処理中は同じ予約を重ねず、次回・前回・結果・原因を保存する。

中断、元フォルダ不在、読み取りエラー、修正競合、前回比50%未満の資料数・分割数・本文文字数の場合は自動確定を保留する。クラウドの未取得ファイルは自動ダウンロードせず記録する。出力・管理領域を走査から除外する。容量不足等の例外でも既存の有効世代を維持する。

## 7. 非機能要件・運用

Python3.12/FastAPI/SQLiteと静的HTML/CSS/JavaScript。利用中の外部通信なし。SQLiteは利用者専用のローカルディスクに置き、クラウド同期場所へ置かない。処理はファイル単位、一覧はページング、重複は内容ハッシュ索引を使用する。

Windows11 x64、Edge/Chrome、日本語・空白入りパス、1093×614/1280×720 CSS画面を検証対象とする。起動時は空きポートを確保し、他アプリを終了しない。製品版1.0.0への昇格はWindows自動試験と利用予定PCでの受入後。性能は1万件試験の実測を記録し、総処理時間は資料量・OCR量・PC構成と併記する。

## 8. 権利・機密・対象外

新しい権利帰属やライセンスを推測で設定しない。継承コードの権利表示と同梱ライブラリのライセンスは維持する。実資料・ユーザー設定・本文DB・社内パスはGitへ追加しない。外部AI接続、アプリ内質問回答、Copilot自動アップロード、macOSのOS常駐予約は初版の対象外。

| FR15 | 文書をアプリ直下に置く | README、要件仕様、概要履歴、基本設計基準をソース直下に保持。利用者ZIPはEXE・HTMLマニュアル・はじめに・補助フォルダに限定 | 配布検査で欠落を検知する |

## 10. 画面遷移と状態表示

```text
起動.bat / ContextgenKai.exe
  └─ ホーム ── 資料フォルダ登録・単発投入 ── 読み取り開始
       ├─ 資料の確認 ── 本文/出典/原本 ── 修正保存・収録除外
       ├─ Copilotへ渡す ── 資料セット作成 ── 出力生成
       │                                  ├─ 確定 → ZIP・指示文
       │                                  └─ 確認待ち → 原因確認 → 明示的確定
       └─ 定期更新・設定 ── 予約/履歴・バックアップ/復元・アプリ終了
全画面左下 → 画像付き操作マニュアル（別タブ）
```

| 対象 | 状態 | 画面で利用者がすること |
|---|---|---|
| ジョブ | queued / scanning / extracting / exporting | 待機・走査・読み取り・出力の段階と実件数を確認する |
| ジョブ | completed | 資料の警告数も確認する。ジョブ完了だけで全原本の完全抽出を意味しない |
| ジョブ | stopped / failed | メッセージを確認して再開。処理済みキャッシュを利用する |
| ジョブ | held | 出力を確定せず、原因と前回出力を確認する |
| 抽出 | ok / partial / empty / error | 読み取り済み・一部欠落・空・エラーとして扱い、警告を確認する |
| 抽出 | protected / needs_conversion / needs_ocr | 保護解除、Office変換、OCR環境の修復を利用者に案内する |
| 文書 | excluded / conflict / active=0 | 除外、修正競合、原本削除を本文抽出の状態と別に管理する |

確認画面は元の抽出本文、保存された修正、出典、警告を区別する。PDF・対応画像はアプリ内で確認できる。Officeのレイアウト再現プレビューは行わず、抽出内容と原本を開く操作を提供する。

## 11. 保存構造とデータモデル

| 保存先 / テーブル | 主な内容 | 整合性・更新規則 |
|---|---|---|
| `catalog.sqlite3: libraries` | id、表示名、絶対パス、folder/upload種別 | 登録パスは重複禁止。登録解除で原本は消さない |
| `documents` | 原本パス・サイズ・更新時刻・ハッシュ、抽出本文、修正文、警告、出典単位 | 登録先＋相対パスで一意。修正元ハッシュで競合検出 |
| `document_search` | パスと有効本文のFTS5 trigram索引 | INSERT/UPDATE/DELETEトリガーで更新する |
| `collections` | 登録先、検索条件、フォルダ条件、選択ID、目的、自由指示 | 個別選択は同じ登録先の資料に限定する |
| `jobs` / `job_files` | 実行状態、件数、エラー、走査完了、資料単位の処理済み印 | 中断・再起動後に処理済み印を利用する |
| `exports` | 世代ID、資料セット、状態、保存場所、検査情報、有効フラグ | 資料セットごとに有効世代は最大1つ |
| `schedules.sqlite3: schedules` | 設定JSON、実行権、PID、ジョブID | 複数プロセスによる同じ期限の重複取得を防ぐ |
| `completions` | 予約ID、実行権、ジョブID、結果・失敗理由 | 古い完了通知で新しい実行を終了させない |
| `imports/` | 単発投入した資料の作業コピー | ブラウザから送られたファイルを利用者専用領域へ保存 |
| `exports/` 以下 | 出力世代・生成中の一時領域 | 全ファイルを書き終えて検査した後に有効化 |

SQLiteはWALとトランザクションを用いる。本文は文書単位で保存し、一覧APIへは本文全件を返さない。原本更新の判定にサイズ・更新時刻を使い、再抽出時には内容ハッシュを照合する。原本が未取得・不在になった場合は、前回の有効な出力を即時削除しない。

バックアップJSONの `schema_version=1` を検証する。復元時は識別子・参照先パスを検査し、原本範囲外への参照を拒否する。元PCと違うパスの場合は登録先を修正して再走査する。バックアップを元資料の保管の代わりにしない。

## 12. API一覧・入力契約

すべてローカル用途。変更APIは `GET /api/status` で得るセッショントークンを `X-Contextgen-Token` に付ける。エラーは原則 `{ "detail": "説明" }`。不正な入力は400または422、参照なしは404、本文修正の競合は409、Origin/Host/トークン違反は403。

| メソッド・パス | 入力 / 出力・処理 |
|---|---|
| GET `/api/health`, `/api/version`, `/api/status` | 稼働・版・登録一覧・件数・ジョブ・予約・画面用トークン |
| GET/POST `/api/libraries` | 一覧 / `{name,path}`でフォルダ登録 |
| PUT/DELETE `/api/libraries/{id}` | 登録変更 / 解除。処理中や予約ありの解除には制約 |
| POST `/api/pick-folder` | OSのフォルダ選択を開き`{path}`を返す |
| POST `/api/uploads` | multipartの複数`files`と任意`name`。作業コピーを登録 |
| GET/POST `/api/jobs` | 履歴 / `{library_id,collection_id?,export_after?}`で開始 |
| POST `/api/jobs/{id}/stop`, `/resume` | 停止要求 / 中断ジョブの再開 |
| GET `/api/documents` | `library_id,q,status,offset,limit`。既定50件、最大200件 |
| GET/PUT `/api/documents/{id}` | 本文・出典・警告取得 / `{text,expected_hash,excluded}`の指定分を更新 |
| POST `/api/documents/{id}/open` | 登録した原本をOS標準アプリで開く |
| GET `/api/documents/{id}/preview` | 登録原本のPDF/画像だけを返す |
| GET/POST `/api/collections`、PUT `/api/collections/{id}` | セット一覧・作成・更新。name/library_id/query/folder/document_ids/purpose/instructions |
| GET/POST `/api/exports` | 世代一覧 / `{collection_id,force:false}`から出力ジョブ開始 |
| POST `/api/exports/{id}/activate` | 保留理由を確認した利用者が明示的に世代を確定 |
| GET `/api/exports/{id}/download`, `/prompt` | 出力ZIP / 指示文テキスト |
| POST `/api/exports/{id}/open` | 世代フォルダを開く |
| GET/POST `/api/schedules`、PUT/DELETE `/api/schedules/{id}` | 予約一覧・作成・変更・解除。OS失敗時は成功扱いしない |
| POST `/api/schedules/{id}/run` | 今すぐ1回実行してジョブIDを返す |
| GET `/api/backup`、POST `/api/restore` | JSONダウンロード / multipart `file`から空の保存領域へ復元 |
| POST `/api/shutdown` | アプリ本体の終了を要求 |
| GET `/manual/` | 同梱の画像付きHTMLマニュアル。公開する文書・画像だけを配信 |

`text:null` は保存済み修正の破棄。文字列での保存は現在の `source_hash` を `expected_hash` に指定する。purposeは `overview`（概要把握）、`compare`（資料比較）、`questions`（確認事項）を使う。

## 14. 0.2.1 利用者向け配布の整理

配布者がソースとOCRをGitで一括管理し、利用者は配布されたZIPを展開してEXEを起動する。開発用コード・試験・設計書・内部来歴・撮影記録・OS固有の開発環境説明はZIPへ入れない。必要なランタイム・OCR・マニュアル画像・第三者の権利表示は `_internal/` に集約する。配布対象を許可リストで選び、`.DS_Store`・`__MACOSX`・`._*`・個人資料・設定を混入させない。画面画像はWindows上の実操作で生成し、撮影環境の記録は開発者証跡だけに保持する。

これは配布面の整理であり、実行物の逆解析を完全に防ぐ要件ではない。ソース公開範囲の変更はリポジトリ所有者の判断とし、無断で公開設定や履歴を変更しない。
