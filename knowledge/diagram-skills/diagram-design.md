# diagram-design — 資料に貼れる整った図

[cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)（MIT、v2.6.120、commit `0b9b10c`、2026-10-24 確認）。リポジトリを読んだ結果で、動かしてはいない。

## 何をするスキルか

文章の指示から、エージェントが SVG を直接書き、1 枚の HTML（+ SVG）にする。PNG / SVG にも書き出せる。図の種類は 45（構成図・フロー・シーケンスに加え、四象限、ガント、ファネル、サンキー、特性要因図、カスタマージャーニー、ワードリーマップ、ピラミッドなど）。

- **ブランドに合わせられる**: Web サイトやフォルダから色とフォントを読み取って 1 回登録すると、以降の図に同じ配色が使われる。文字の濃さ（コントラスト比）は自動で検査する。
- **書き出しの型**: `slide-16x9`（1280×720）と `slide-4x3`（1024×768）がある。PNG は 2 倍の解像度。A4 横の型はないので、その場合はサイズを個別に指定する。
- draw.io / Mermaid / Excalidraw を読み込める。

## ルール集（指示文に書き写せる部分）

スキルの SKILL.md にある、図を減らすためのルール。図を描かないツールでも、図を描く側（Copilot など）への指示文に使える。

- 密度の目安は 10 段階の 4。要素が 9 個を超えたら、たぶん 2 枚の図。
- 強調色（accent）は 1 枚に 1〜2 か所まで。
- 影は使わない。枠線を使う。
- 配置で分かる関係には線を引かない。すべての線が情報を運ぶ。
- 「足し終えたら完成」ではなく「もう削れなくなったら完成」。
- 出す前に確認する: 要素を 1 つ消せないか、矢印を 1 本消せないか、ラベルを 1 つ消せないか（色や形で既に伝わっていないか）。
- 同じ形のカードを 3 つ並べない。幅や扱いに差をつける。

## 入れるときの注意

- 導入: `npx skills add cathrynlavery/diagram-design`（Claude Code のプラグインとしても入る）。PNG / SVG の書き出しには Python 3 が要る。
- 図を開くと Google Fonts を読み込む。社内資料や通信できない環境では `--system-fonts` で PC のフォントだけを使う。`self_check.py --offline` で外部読み込みが残っていないかを確かめられる。
- 日本語フォントは同梱していない。PC 側の游ゴシック・ヒラギノ・メイリオに頼る。
- 静的な図なので、操作はできない。正確さの自動検査は弱い。

## Viniprj での扱い

`pptx-web-bridge/` はこのスキルを取り込まない（アプリは図を描かない）。上のルール集を、Copilot に渡す指示文の「型ごとの作り方」に書き写すのが使い道。今の型の語彙は `diagrams.TYPES` が正なので、図の種類を増やすときはそこから。取り入れたら `pptx-web-bridge/docs/99` に判断を 1 行残す。
