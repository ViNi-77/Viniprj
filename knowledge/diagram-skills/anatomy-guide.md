# anatomy スキル 手順書 — 質問を「動かせる機械」にする

> 出典：Elvar（@elvar_official）「How I Turn Any Question Into a Machine You Can Run」（2026-10-18）
> https://x.com/elvar_official/status/2111831136171151589
> ※本書は上記記事の要点を日本語で再構成したもの。プロンプトは記事の構造をもとに書き直したテンプレート。

---

## 概要

- Claude Code 用の無料スキル **anatomy**（作者：wheresryan22／MITライセンス／依存なし／サンプル8機種同梱）を使う
- 「〇〇はどう動くの？」への答えを、**ボタンで1ステップずつ操作できる機械の図解**として、単体HTMLページで生成する
- 文章の説明は読み飛ばされるが、操作できる図解は何度も触られる。特に子ども向け教材で反響が大きい
- 作例：https://visual-learning.app （筆者が作った12機種を公開）

## 完成形を構成する6要素

| # | 要素 | 内容 |
|---|------|------|
| 1 | 機械 | 細かい部品（ボルト、メーター、トレイ等）で組まれた、実物と分かる機械 |
| 2 | ボタン | 手順ごとに1つ、順番通り。次のボタンしか押せない。手動／自動ループの切替スイッチ付き |
| 3 | 窓 | 実際に仕事をしている部分の断面。原因と結果を同時に見せる |
| 4 | 数値 | メーター・内蔵ディスプレイ・図の下のチップで表示。**すべて1つの実物モデル（関数）から算出** |
| 5 | 言葉 | ステップごとの一行ヒント＋動作に添える擬音（ゴリゴリ、カチッ、プシュー等） |
| 6 | ビッグアイデア | 図の下に一文だけ。例：「圧力を生むのはバネ」 |

## 必要なもの

- Claude Code（利用可能なClaudeプラン）
- Node.js 22.20 以上（インストーラーが要求）
- Google Chrome（スキルがヘッドレスブラウザで自己チェックする）
- ffmpeg と Python 3（動画化する場合のみ。Claude Code に頼めば導入してくれる）

---

## Step 1. スキルをインストール

```bash
npx skills add wheresryan22/anatomy -g -a claude-code
```

npm を使わない場合はスキルフォルダに直接クローン：

```bash
git clone https://github.com/wheresryan22/anatomy.git ~/.claude/skills/anatomy
```

Claude Code を開き `/anatomy` で起動。

> ⚠ 外部リポジトリのスキルなので、業務環境で使う前に中身を確認しておく。

## Step 2. 質問を選ぶ

**「動く部品」と「数値」がある質問**が向いている。自分でも答えられない質問を選ぶと良い。

候補例：
- トイレは流した後どうやって水が溜まる？
- 自転車のギアはなぜ漕ぐのを楽にする？
- 鍵はどうやって錠を開ける？
- エレベーターはどうやって正しい階で止まる？
- 毎月1万円の積立は複利でどう増える？

## Step 3. 機械を生成する

ポイントは **絵を描く前に、実物のモデルを純粋関数として書かせる** こと。全ての表示値が同じ関数から出るので、メーターと時計と秤が食い違わない。

```text
/anatomy 「[質問：例）エスプレッソマシンはどうやってコーヒーを淹れる？]」に答えて。

図ではなく機械で答えること。[機械の構成：例）レバー式エスプレッソマシン、横にグラインダー、
ポルタフィルター、タンパー、ミルクジャグ、秤に乗ったカップ] を、細かい部品で組んだ
実物らしい姿で、アイソメトリック視点の単体HTMLページとして作って。

手順は左側に縦並びのボタンにする：[例）18gを挽く][タンピング][セット][レバーを引く]
[離す][ミルクをスチーム][注ぐ][新しいカップ]。押せるのは次のステップだけ。
各ボタンは機械そのものの上でその工程を再生する。

本当の仕事が起きている部分に窓（断面）を開けて：[例）グループヘッド内のピストン、バネ、水]。
原因と結果が同時に見えるように。

描画の前に、実物の小さなモデルを純粋関数として書くこと。画面上の数値はすべてそこから出す：
[例）粉18g→抽出36g・27秒、抽出圧9barから6barへ低下、ボイラー1.1bar、ミルク4℃→62℃]。
メーター、機械内蔵ディスプレイ、図の下の小さなチップでライブ表示する。
数値の正しさに確信がなければそう明記し、根拠を示すこと。

図の下に一行：「ビッグアイデア：[例）圧力を生むのはバネ]」
```

設計原則：
- **モデルが先、絵が後**。ビルド時に自己チェック値（例：抽出27.0秒、最初の一滴5.4秒、36g）を出力させると検証しやすい
- **ビッグアイデアは一つ**。一文で言えないなら、2つを説明しようとしてどちらも伝わらない
- 他の機械も、このプロンプトの [ ] を差し替えるだけで作れる

## Step 4. ひと目で分かるようにする

数値は簡略化せず、見せ方だけを易しくする。基準は **「7歳児が一読で分かるか」**。

```text
数値は単純化せずに、ひと目で分かるようにして：
- 各ステップに上部の短いヒント（何が起きていて、なぜか）。7歳児にも分かる言葉で
- 番号付きの大きなピル型ボタン。実行中は点灯、完了したステップは薄く
- 各動作に手書き風の擬音を小さく添える
- 実時間より速い／遅い再生のときは速度バッジ（×4、×1/20など）を実秒数から計算して表示
- ステップ上部に2モードのスイッチ：既定は「手動」（押すまで動かず、次のボタンが点滅）、
  「自動」は全工程をループ再生。選択は次回訪問時も記憶
- ステップ1に戻す「最初から」リンク
- （任意）図の下に番号付きカード3枚、小さなマスコット、全工程を再生する「見せて」ボタン
```

メモ：実時間27秒の抽出を6.5秒で再生 → バッジは×4、ショットクロックは27秒のまま。エンジンのように速い動きは逆に×1/20で再生。

## Step 5. 見た目を整える

テイストは **手描きの絵本風**（技術図面ではない）。

```text
スタイル：技術図面ではなく、手描きの子ども向け絵本風に。
- 濃紺の線（1.2px）、フラット塗りで1色につき3トーン（上面が最も明るく、側面は暗く）
- クリーム色の紙背景（#f5f0e5）、物ごとに大胆な1色、金属部はクロームと真鍮
- 図の下にカラースウォッチを置き、機械の色を変えられるように
- 影は短く輪郭のはっきりした暖色グレー（#ddd4c3）で各物体のすぐ後ろに。青・紫は使わない
- ダイヤル、表示、ラベルは他の物に隠れない面に配置
```

各指定は初版の失敗（長い紫の影、グループヘッドに隠れたメーター）を潰すためのもの。

## Step 6. 批評家目線でチェックさせる

```text
見せる前に、批評家のように確認して：
1. 各ステップの中間で静止画を撮り、部品の重なり・枠からはみ出す文字・モデルと食い違う数値を探す
2. 1秒を超える動きは0.1秒刻みでスキャンし、フレームごとの変化ピクセル数を数える。
   前後の3倍以上変化するフレームは「飛び」なので特定して修正する
3. 1秒を超える動きは連続的に。事前に描いたポーズを切り替える方式にしない
確認した内容と修正内容を報告し、静止画を見せて。
```

実例：通常フレームの変化は900〜1,400px程度だったが、ある角度の1フレームだけ95,245px変化 → レバーが巨大な黒い円になるバグを発見・修正。修正後は612フレーム全てで飛びなし。

## Step 7. 動画にする（3つのプロンプトを順に）

**① 収録できるようにする**

```text
ツアーを収録可能にして：
- window.seek(t) を追加し、0から時刻tまでを再生した状態を描けるように（任意のフレームを任意順に描画可能に）
- URLに ?render があればページ自身の時計を止める
- 各ステップ開始の少し前に、カーソルがボタンへ移動して押す様子を描く
- 全体を36秒に収める：ステップ間0.7秒、最初のクリックは0.9秒、[メインの見せ場]は最も遅いステップのまま
```

**② 録画する**

```text
?render付きでヘッドレスChromeで開き、60fps・1500×1320で全フレームをwindow.seek()して
スクリーンショットし、ffmpegへパイプしてH.264（yuv420p、faststart）で書き出す。
その後3秒ごとに1フレームのコンタクトシートを作って見せて。
```

**③ 音をつける**

```text
サンプル音源・ライセンス素材を使わずコードで作曲：84BPM・36秒のローファイBGM
（Fmaj7–Em7–Dm7–Cmaj7のエレピ、丸いベース、1小節目以降にブラシドラム、かすかなレコードノイズ）。
映像の正確な秒数に合わせて効果音を重ねる（ボタンのクリック、グラインダー音、スチーム、抽出の細い水音）。
-14 LUFS、トゥルーピーク -1dB未満でマスタリングし、ffmpegで動画に多重化。
```

画面録画はゆっくりした動きでフレーム落ちするが、seek方式なら常に60fps（例：2,160フレーム、36秒、4.5MB）。

## Step 8. 残りを並列で量産する

1機種が完成したら、1機種1エージェントで並列生成。

```text
次の機械を1機種1エージェントで並列に作って：[機械のリスト]
全エージェントがエスプレッソマシンのルール（同じ見た目、ステップボタン、
メカニズムの窓、全数値を駆動する1つのモデル、ビッグアイデア1つ）に従うこと。
それぞれに「証明すべき事実」と実際の数値を与える：[例）電子レンジでチョコを溶かし、
溶けた点の間隔6.12cmから光速を測る]
各エージェントは自分のフォルダで作業し、共有ファイルは編集せず、
報告前に自分の静止画を確認すること。
```

**最重要は「事実」**。「電子レンジを作れ」だと皿の入った箱を描くだけだが、「チョコで光速を証明せよ」なら定在波を描かざるを得ない。

## Step 9. 1つのサイトにまとめる

2〜3個できたらサイト化する。

```text
図解を小さなサイトにまとめて：
- トップページに図解ごとのカード（見せ場の静止画、名前、何に答えるかの一行）
- 各図解は個別ページ。上部ナビに全機種のサムネイル付きメニュー、←→キーで機種切替
- Space/Enterで次のステップを実行
- 各ページに1200×630のOGP画像（ステップ途中の静止画、絶対URL）でX共有時にカード表示
- 外部リンクは新しいタブで開く（機械の状態を保つため）
- Vercelにデプロイし、独自ドメインを向ける
```

カードの一行が「売り」になる。例：「9気圧はどこから来るのか、なぜバネで足りるのか」

## ボーナス. 壊して学ばせる

```text
[例）粉量 9g〜22g] のスライダーを1つ追加し、動かしたらモデルを再計算して
[例）少ないと速く薄く、多いと詰まる] 結果を同じメーターと数値に表示して。
```

機械を壊せる人は、各数値が何をしているかを自分で発見する。

---

## 要点まとめ

1. **モデルが先、絵が後** — 全数値を1つの関数から出して矛盾をなくす
2. **一図一メッセージ** — ビッグアイデアは一文で
3. **7歳児テスト** — 子どもが一読で分かるヒントは、大人には0.5秒で伝わる
4. **自己検証をプロンプトに組み込む** — 静止画とピクセル差分で確認させ、修正内容を報告させる
5. **量産時は「証明すべき事実」を与える** — 曖昧な指示では表面的な図しか出てこない
