# anatomy — 触って分かる機械の図解

[wheresryan22/anatomy](https://github.com/wheresryan22/anatomy)（MIT、commit `1482e84`、2026-10-18）。リポジトリを読み、キットを使って実際に 2 台の機械図解を作った。使い方の手順書は [anatomy-guide.md](anatomy-guide.md)。

## 何をするスキルか

「〇〇はどう動くの？」への答えを、斜め上から見た立体の機械として描き、単体 HTML にする。中心の考え方は「物そのものが説明」。箱やラベルを並べるのではなく、仕組みと 1 対 1 で対応する機械を考え出す。

- 最初に実物の小さなモデルを純粋関数で書き、画面の数値はすべてそこから出す。メーター・表示窓・読み出しが食い違わない。
- 完成前に、Chrome で画面を撮り、部品の重なり・浮き・沈み込み・線の端・描画順を自動で検査する（`--audit`、`lines.mjs`）。
- 動き（時間基準の補間、ばね、アイドルツアー、分解）の作法が `references/motion.md` にまとまっている。
- 必要なもの: Node 20.10 以上、Chrome / Chromium。動画にするなら ffmpeg。手順書には Node 22.20 以上とあるが、スキル本体の記載は 20.10 以上。

手順書の「ボタンで 1 ステップずつ進める」「7 歳児テスト」「絵本風の見た目」は、記事の筆者がプロンプトで指定した使い方で、スキルの標準の動きではない。

## 実践で分かったこと

2 台作った: 生成 AI の仕組みを机の上の架空の装置にしたもの（差し戻し）と、ノイズキャンセルの測定台（ヘッドホンの断面・スピーカー・オシロスコープ）。

### 題材と見せ方

- **架空の装置は伝わらない。** 比喩を物にした架空の機械は「何の機械か分からない」と差し戻された。受講者が実物を知っている物（ヘッドホン、エスプレッソマシンなど）を選ぶ。
- **静止に近いと「地味」と言われる。** ボタンを押すと数値が変わるだけでは足りない。開いたら自動で 1 周する、台の上を波紋が広がる、配線を信号の光が走る、信号が通る部品が点く、部品が震える、断面を分解して見せる、を最初から設計に入れる。
- **唯一の光る点（`lit`）が見えているかを最初に確かめる。** 耳の位置の測定点が板の裏に隠れて見えず、図の主役が消えていた。断面の切り方とカメラの向きを決めた時点で拡大して確認する。
- **主役を大きく撮る。** 台を広く取ると機械が小さくなり、断面の中身が 50 px ほどになった。周りの物を減らして主役に寄せる。

### キットの使い方

- 日本語ラベルは表示できる（Linux の IPA ゴシックで確認。Windows の Meiryo UI は未確認）。`pageHtml` は `lang="en"` 固定なので出力を `lang="ja"` に置き換え、CSS の `--anatomy-mono` と `body` に日本語フォントを足す。カードの四隅の文字は折り返さないので、長い日本語は図の下の HTML に置く。
- 依存なしで配るには、`kit/` と `scripts/` を `vendor/anatomy/` に複製し、取得元 commit を記録する。生成物は単体 HTML で外部 URL を含まない。
- 面に描く印（点・文字・配線）は、別の項目にせず、乗っている部品の `after` に入れる。別項目にすると描画順の並べ替えで部品の面に隠れる。
- 面に文字を貼る `sideMatrix` は、法線が ±y の面は `"left"`、±x の面は `"right"`。逆にすると文字が歪む。
- 台の上に描く線（波紋など）は、台の部品を作る前に用意する。後から作ると台の `after` に入らない。
- 配線を含む項目は形より大きく描かれるので、被覆率の検査だけ `cover` で除外する。
- **監査を通っても目視は要る。** 描画順の検査が拾わない重なり（オシロの枠が画面と波形を覆う）があった。4 倍に拡大して見る。直し方は、重なる 2 つを 1 つの項目にまとめること。
- 分解は raptor の作例と同じ方式で作れる: 部品に移動ベクトルを持たせ、ばね（stiffness 64、damping 14.2、35 ms ずらし）で動かし、`A.recorder(P, { order, spring })` に同じ定数を渡すと、監査が分解の途中の状態まで検査する。

### 時間

1 台で数時間かかる。幾何の手直しより、題材と構図の判断のほうが結果を左右した。作り込む前に、静止画を 1 枚撮って「何の絵か」が伝わるかを確かめる。

## Viniprj での扱い

`ai-water-footprint/` の「1 回の質問で ◯ mL が蒸発する」を冷却塔の機械で見せる案が一番合う（[README の使い道](README.md#4-viniprj-での使い道)）。数値を `js/data.js` だけに置く決まりと、anatomy の「計算式は 1 つ」は同じ考え方。生成物の単体 HTML だけを置けば、ビルドなし・依存なしの決まりも守れる。
